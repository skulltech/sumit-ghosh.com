I help founders and engineering teams build AI features that work inside their products, from the first implementation through deployment and the operational details that follow.

I'm the CTO and technical cofounder of [Jurisphere](https://www.jurisphere.ai/), where I lead engineering and contribute directly to the code. My experience spans document processing, retrieval, agents, application development, and infrastructure. [Here's a closer look at that work]({{ '/work/jurisphere/' | relative_url }}).

## Problems I can help with

- **Document processing and search.** Turn uploaded files and scanned documents into usable content; build retrieval with source references and appropriate access boundaries.
- **AI features inside an existing product.** Assistants, tool use, structured extraction, and review workflows integrated with your application's data and interface.
- **Getting an AI workflow ready for production.** Handle retries, interrupted work, streaming, conversation state, provider failures, and the telemetry needed to understand them.
- **Deployment and backend engineering.** Build the API and background processing behind the feature, or improve an existing system's deployment and operations.

My strongest fit is a team with a concrete product problem and someone who can make decisions about scope. The domain can be legal, financial, operational, or any other area where documents and existing workflows matter.

## How an engagement starts

For an existing system, we can start with a technical assessment: inspect the relevant workflow, identify the main failure modes, and produce a prioritized implementation plan.

For a well-defined feature, we can agree on an implementation sprint with explicit acceptance criteria and a handover. Ongoing engineering work is also possible when the scope and working arrangement fit.

I'll confirm availability, scope, and pricing in conversation.
